# Качество 3D-фигурок: анализ движков и настройки (18.11.2026)

Это технический выбор из официальных API-документаций и открытого описания студий, **не независимое сравнительное измерение качества фотографий**, не оценка геометрической точности и не доказательство печатности. Повышенный polycount/8K сами по себе не гарантируют хорошую скульптуру.

## Изученные решения

| Система | Полезные идеи | Что внедрено |
| --- | --- | --- |
| Tripo H3.1 | Ультрадетализация, настоящие мультиракурсы, 8K PBR, отдельно генерируемые части, фиксированный model_seed | ✅ H3.1 профили sculpt / display / parts, canon front-left-back-right |
| Meshy 7.1 | Ultra 4K из одного изображения, Ultra 2K из нескольких, сохранение исходной геометрии без remesh, отдельный текстурный режим | ✅ optional API-адаптер и строгие ограничения режимов |
| AI3D Studio | Многодвижковое рабочее место, QA, remesh, print split | ✅ архитектурный подход «несколько движков → аудит → экспорт»; сторонний проприетарный код не копировался |
| Blender + 3D Print Toolbox | Manifold/nonmanifold, толщина, площадь/объём, нависания | ✅ offline mesh QA, Blender headless-скрипт рендеров; полноценные проверки толщины выполняются в установленном Blender |
| Hunyuan3D / TRELLIS.2 | Возможные альтернативные self-hosted генераторы | Не включены: потребуют GPU, весов и отдельной приёмки; не устанавливались как фиктивные интеграции |

## Конфигурации максимального качества

### Tripo H3.1

| Профиль | Модель | Геометрия | Текстуры | Когда выбирать |
| --- | --- | --- | --- | --- |
| `sculpt` (по умолчанию) | `v3.1-20260211` | `geometry_quality=detailed`, adaptive face count | Выкл | Фигурка для печати, скульпт |
| `display` | `v3.1-20260211` | Detailed | `texture_quality=extreme`, 8K, PBR, texture v3.5 | Экранная цветная 3D-модель |
| `parts` | `v3.1-20260211` | Detailed, `generate_parts=true` | Выкл, `pbr=false` | Раздельная модель под дальнейшую обработку |
| `economy` | `v3.1-20260211` | Standard | Выкл | Черновой обзор формы |

**Специально не задаём face_limit=2M:** Adaptive polycount может выделить полигоны там, где они полезнее. Достижимый верхний предел Tripo не означает, что любой результат должен иметь столько треугольников. Более высокий предел может затруднить импорт и постобработку.

Ограничение: `generate_parts=true` несовместим с включёнными текстурами и PBR, поэтому режим `parts` специально их отключает. Autofix исходной фотографии по умолчанию **выключен**: он может искажать характерные черты реального человека. Для низкокачественного изображения доступен `--autofix-image` как сознательный выбор.

По официальной таблице Tripo H3.1 (на дату исследования) базовая image-to-3D без текстур — 20 кредитов, Ultra detailed geometry добавляет 20; 8K texture добавляет расходы. Тарифы могут изменяться. **Никаких автоматических массовых генераций обоих движков.**

### Meshy 7.1

| Профиль | 1 фото | 2–4 фото | Материалы |
| --- | --- | --- | --- |
| `sculpt` | `geometry_resolution=4k` | `geometry_resolution=2k` | Выкл |
| `display` | 4K | 2K | 8K texture, `meshy-7` texture model, PBR |
| `economy` | Standard | Standard | Выкл |

`should_remesh=false` сохраняет исходную геометрию, как рекомендует официальная документация для наиболее детализированного результата. Для низкополигональной версии выполняйте **отдельную** ретопологию после сохранения оригинала.

Важно: `4k` **не поддерживается** Meshy multi-image API. Не использовать устаревшие `ultra_mode`, `lowpoly` или `meshy-7` как геометрическую модель (последняя выводится из эксплуатации 31.12.2026).

### Качество референсов — самый важный вход

- Приоритет: 4 настоящие фотографии **того же объекта**, front/left/back/right. Если их нет, используйте 2–3 настоящие, а не домысливайте внешность по нейросетевым картинкам.
- Виден весь объект целиком, без обрезанных пальцев, обуви, ушей, лап или основания.
- Согласованный масштаб, ракурс, положение частей, рассеянный свет, нейтральный фон.
- Желательно чёткие изображения не менее 512px по короткой стороне; минимальная рекомендация Tripo 256×256.
- Зеркальные изображения одного ракурса не считаются новым настоящим видом.
- Для людей контролировать реальную похожесть вручную — ни один отсчёт треугольников её не измеряет.

Команда `tflex-reference` измеряет размер, контраст, обрезание по alpha и относительный индикатор резкости. Низкие оценки — повод посмотреть изображение, но **не запрет** и не абсолютный сертификат.

## Приёмка геометрии

1. `tflex-audit` — watertight, normals, degenerate faces, connected shells, volume.
2. `tflex-pipeline` — сохранение исходного аудита и STL/OBJ только после первичной проверки.
3. `scripts/blender_review.py` — Blender создаёт фронтальный, боковой, задний и правый рендеры; `tflex-contact-sheet` собирает 2×2.
4. Визуальная проверка: лицо/глаза/пальцы/волосы/хвост/скрытые части, стыки одежды, форма основания.
5. Для печати: Blender 3D Print Toolbox + слайсер — минимальная толщина, самопересечения, опоры, усадка/материал, ориентация, размер платформы.
6. Фактический импорт STL/OBJ в установленный T-FLEX CAD (не автоматизирован).

**Критический критерий:** `topology_gate=true` значит только «прошёл базовый технический порог», но `verified_print_ready=false` остаётся до проверки материала/слайсера/человеком.

## Нельзя приписывать системе то, что она не умеет

- Нет автоматического подтверждения точной похожести человека и «правильности» затылка по одному фото.
- Нет безошибочного автоматического ремеша и сохранения всех микродеталей.
- Нет измерения минимальной толщины на каждом участке.
- Нет прямого T-FLEX CAD Open API или проверенного Windows-хоста.
- Нет независимого бенчмарка, по которому Meshy или Tripo всегда лучший.
