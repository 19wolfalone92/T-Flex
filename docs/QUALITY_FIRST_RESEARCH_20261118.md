# QUALITY FIRST — доказательная ревизия 18 ноября 2026 г.

Цель: не повторить ошибку мультимедийной студии, где множество подключённых сервисов не гарантировало пригодность конечного результата. Установка/добавление провайдеров НЕ является критерием готовности. Готовность доказывается одним объектом от входного изображения до проверенного STL, с визуальным контролем и слайсером.

## Что показала независимая проверка рынка

### Rap idata / benchmark.ai — многократные слепые человеческие оценки (на дату исследования)

Публичный датасет с **49 261 попарным сравнением, 262 668 голосами, 357 исходными изображениями и 13 моделями**. Все модели получают одинаковый референс, человеческие судьи видят одинаковые 10-секундные обороты, изображения в сером материале (фактическая форма) оцениваются отдельно от цветных (внешний вид). Рейтинг **на момент чтения**, не константа:

- Hi3D v3.0: 1366 overall / 1304 geometry / 1440 appearance (#1).
- Meshy v7.1: 1298 / 1249 / 1358 (#2).
- Tripo H3.1: 1261 / 1224 / 1304 (#4).

Источник и методика: https://huggingface.co/datasets/Rapidata/image-to-3d-single-object-human-feedback-benchmark/blob/main/README.md
Это **single-image**, а не multiview и не проверка физической печати. Статистическая высокая позиция Hi3D НЕ гарантирует её победу на конкретных фото фигурок.

### Top3D Arena, октябрь 2026 — отдельный рейтинг, другая методика

В общем рейтинге Tripo AI v3.1 (#1, 1111), Rodin Gen 2.5 (#2, 1106), Hi3D v3.0 (#3, 1095), Meshy 7.1 (#4, 1079).

Источник: https://www.top3d.ai/leaderboard/seasons/oct-26

**Рейтинги противоречат друг другу**: целевые критерии, выборки и режимы отличаются. Универсального победителя нет. Нельзя утверждать «Meshy / Tripo лучший» лишь по маркетинговому тесту производителя или по максимальному количеству полигонов.

### Реальные тесты печати и визуальный контроль

- All3DP, июнь 2026: Meshy, Tripo, Hi3D тестировались с референсами, слайсерами и настоящей печатью. Результаты требуют доработки, никто не заменяет CAD, сканирование и ручной скульпт.
  https://all3dp.com/2/ai-generated-3d-model-best-tools/
- All3DP, отдельный тест: Tripo показал лучшее соответствие отдельному исходному изображению, чем Meshy/Hi3D, но это всего **один** объект.
  https://all3dp.com/4/from-image-to-print-ready-3mf-we-found-tripo-beats-meshy-hitem3d-for-accuracy/
- SceneOS сравнил Tripo H3.1, Meshy 7.1, Rodin 2.5, TRELLIS 2 на одном наборе из трёх сюжетов: оценки наиболее похожего изображения присуждались чаще Meshy/Rodin, хотя Tripo выдавал более плотную сетку; это ещё раз показывает, что 2M треугольников не равно качеству.
  https://www.sceneos.io/kb/3d-generators-compared/
- Scenario: крупный image-to-3D benchmark демонстрирует textured / clay / wireframe. Методологически **обязательно** отдельно оценивать clay, чтобы не принять нарисованные normal-map детали за физический рельеф.
  https://www.scenario.com/explorations/image-to-3d-benchmark/

## Выбор ПО: минимальный проверяемый стек

**Базовый движок: Tripo H3.1** — уже есть рабочий GitHub Secret TRIPO_AL, проверка авторизации прошла; поддерживает multiview и detailed geometry. Включается в контролируемом эксперименте первым, без 8K PBR для монохромной 3D-печати.

**Честный второй кандидат: Meshy 7.1** — уже есть ChatGPT-плагин, формально 4K geometry в single-image и 2K в multi-image. Не подключать отдельный дорогой API к GitHub без необходимости: ChatGPT Meshy и GitHub-клиент — разные авторизации.

**Challenger только после реального сравнения: Hi3D v3.0** — первое место в Rapidata и акцент на печать в All3DP. **Не подключён**; не создавать ложный список из 10 «внедрённых» нейросетей. Проверять API/права/стоимость, только если два действующих движка не дают нужного результата на контрольном наборе.

Rodin Gen-2.5, TRELLIS.2, Hunyuan3D 3.1 Pro и photogrammetry — перспективные, но **не добавлять в production** без превосходства на целевой фигуре. Для точного воспроизведения уже существующего реального объекта предпочтительнее проверенная фотограмметрия/сканирование с многими перекрывающимися фото; нейросеть по 1 картинке закономерно домысливает невидимую сторону.

## Правильный процесс генерации

1. **Зафиксировать задачу до генерации**: статуэтка или портретный бюст; FDM/смола; целевая высота; требования к лицу, волосам, пальцам, хвосту, толщине и возможности печати.
2. **Подготовить исходный набор**, фото действительно с разных сторон одного реального объекта. Не засчитывать AI-сгенерированный задний вид как фотографическое доказательство.
3. **Сделать ограниченный пилот**: один заданный референс → Tripo H3.1 sculpt detailed → скачать GLB → clay+color full rotation → Blender/mesh audit → при необходимости Meshy 7.1 на том же исходнике. Один генератор за раз; фиксировать credits consumed, версию, параметры и промпт.
4. **Слепое попарное сравнение**: привести оба меша к одной высоте, общей камере и освещению; ракурсы front/left/back/right, отдельно без текстур. Не сравнивать один с PBR, а другой с отключёнными материалами.
5. **Оценить качества** по рубрике ниже; не объявлять победителя по polycount, размеру файла или «красивой картинке» приложения.
6. **Прогнать геометрию и сборку в Blender**, затем в слайсере и установленном T-FLEX. Файл должен быть полезен для поставленной задачи, а не только открываться в превью.
7. **Если оба не прошли**, зафиксировать дефекты и только тогда сравнить Hi3D v3.0 на том же исходнике; без массового добавления API.

### Балльная рубрика качества (оценка оператором по 0–5, фиксируется до испытания)

| Параметр | Вес | Суть |
| --- | ---: | --- |
| Соответствие референсу | 30% | лицо / узнаваемые детали / силуэт / пропорции |
| Настоящая геометрическая детализация | 25% | волосы, складки, пальцы и рельеф видны в **clay** |
| Согласованность со всех сторон | 15% | не пропадают/не дублируются части, нет выдуманного второго хвоста |
| Топология | 15% | отсутствие дыр, самопересечений, ненужных плавающих частей |
| Практическая печатаемость | 15% | минимальная толщина, прочность, устойчивость, опоры в конкретном слайсере |

**Безусловные STOP-условия:** грубые нарушения формы/узнаваемости; невозможно исправить критические дефекты без потери деталей; проверка толщины/слайсера не пройдена. Не называть экспорт «готовым к печати», пока нет подтверждения печатного процесса. Сравнение осмысленно для одного способа печати и масштаба.

## Проверка Blender — не на уровне синтаксиса

В проект добавлена отдельная native GitHub Actions smoke-проверка: устанавливает реальный Blender на Ubuntu, импортирует **синтетический OBJ 120-мм размера**, рендерит четыре ракурса с оригинальными материалами и четыре на нейтральном глиняном шейдере, генерирует две контактные таблицы и проверяет файлы/отчёты. Открытые/пользовательские фотографии в CI не передаются. Результаты сохраняются на 7 дней артефактом `blender-native-smoke-qa`.

**Это доказывает исполнимость Blender-скрипта в Linux CI, но не работу на компьютере пользователя и не качество AI-фигурки.** Реальное качество проверяем только на выходах генераторов.

## T-FLEX CAD: ограничение, которого нельзя обойти скриптом

T-FLEX CAD принимает STL/OBJ как полигональные 3D-изображения; в бесплатной/студенческой редакциях сторонние Open API приложения не поддерживаются. Реальный native plugin возможно делать после определения версии, лицензии и проверки поставляемого SDK.

Официальные источники:
- https://www.tflexcad.ru/help/cad/18/28_apps_example.htm
- https://www.tflexcad.ru/download/t-flex-cad-free/limitations.php
- https://www.tflex.com/resources/tflexcadst/limitations.php

### Gate до новых интеграций

Новый генератор добавляем в постоянную архитектуру **только если** на одних и тех же референсах он (а) проходит технический pipeline, (б) улучшает визуальную рубрику и/или снижает ручную доработку, (в) экономически и юридически подходит, (г) отдаёт доступные модели, а не только рендер. Иначе не добавляем.
