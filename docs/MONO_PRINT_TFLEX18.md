# T-FLEX CAD 18 + Hi3D 3.0 + монохромная 3D-печать

**Целевая версия — T-FLEX CAD 18 (Windows, актуальная и документированная на ноябрь 2026).** Надёжной общедоступной статистики о том, какая версия установлена у большинства пользователей, нет; поэтому выбрана *актуальная поддерживаемая версия 18*, а не выдуманная «самая популярная».

## Что по-настоящему реализовано

1. Отдельный официальный Hi3D v3.0 клиент через Basic AK/SK → Bearer токен, read-only `balance`, генерация из 1–4 реальных фотографий, проверка задания и скачивание GLB. **Не совершает дорогостоящий запрос без `--yes-spend-credits`.**
2. Два профиля:
   - `quality`: геометрия `2048quality` / 2 млн треугольников; разумное первое испытание.
   - `master`: `2048master` / 5 млн треугольников; самый детальный официальный режим, не обязательно лучший для каждого референса и более требователен к памяти/времени.
3. **Технология под монохромный принтер**: Blender разделяет *предварительно проверенный* STL на две цельные части, делает в каждой парные отверстия, сохраняет два отдельных штифта и испытательную втулку. Сохраняет два независимых набора STL: общие координаты для сборки в T-FLEX CAD, и детали с Z=0 для слайсера. Также сохраняет спецификацию `parts.csv` и геометрию штифтов/размеры в `assembly.json`.
4. В отдельном GitHub Actions workflow устанавливается настоящий Blender, режется **синтетический тестовый цилиндр 120 мм** и все STL проверяются независимой библиотекой `trimesh`. Это не означает, что реальные AI фигурки всегда безопасно разделятся.
5. **Мост T-FLEX CAD 18** реализован через официально поддерживаемую настройку *Внешнее приложение* из меню «Команды пользователя». Запускает Python+Blender-пайплайн из окна T-FLEX и открывает каталог результатов. **Это рабочий локальный механизм, а не нативная Open API DLL.** Для истинного CAD-плагина потребуются локальные Visual Studio, T-FLEX CAD 18 и его SDK/лицензия.

## Ключи Hi3D

В GitHub Secret по отдельности:

- `HI3D_ACCESS_KEY`
- `HI3D_SECRET_KEY`

Сам ключ нигде не выводится; GitHub не позволяет ассистенту прочитать значение. Проверка: GitHub Actions → **Hi3D 3.0 authentication and balance — READ ONLY**. Использует `POST /auth/token` и `GET /balance`, без создания модели.

Локально (PowerShell):

```powershell
$env:HI3D_ACCESS_KEY="your access key"
$env:HI3D_SECRET_KEY="your secret key"
tflex-hi3d balance
```

## Hi3D 3.0: запуск только по явному разрешению на расходы

```powershell
tflex-hi3d submit --front .\private\front.png --profile quality
# DRY RUN показывает режим, ничего не списывает.
# Платно, только после оценки стоимости:
tflex-hi3d submit --front .\private\front.png --profile master --yes-spend-credits
tflex-hi3d status TASK_ID --wait
tflex-hi3d download TASK_ID --output .\models\hi3d.glb
```

Если фото несколько: `--front` + `--back`, `--left`, `--right`. Важно: **порядок Hi3D = front, back, left, right**, что отличается от порядка Tripo (front, left, back, right); соответствие закодировано и тестируется.

Для одноцветной печати профили по умолчанию создают только геометрию. Текстуры PBR **не добавляют печатных деталей**.

## Рекомендуемый вариант для сложной разноцветной фигурки: официальный Hi3D Split-to-Print

Hi3D предоставляет специальный API **3D Model Split** с шаблонами разбиения персонажей и соединительными элементами. Мы реализовали дополнительную интеграцию с официальным endpoint `/split/create-task`, а не пытались заменить её одним горизонтальным разрезом:

- `--template a` — 6 частей; `b` — 5; `c` / `d` — по 4; `e` — 3; `f` — 2.
- `--joint pin` — соединительные штифты; альтернативы `ball`, `dovetail`, `none`.
- `--kind general --level medium` — обычные предметы, не человек/персонаж.

Документация производителя:
https://docs.hi3d.ai/en/api/api-reference/list/split-create-task

```powershell
# Сначала ТОЛЬКО проверить параметры, без обращения к API:
tflex-hi3d split --mesh .\models\figurine.glb --kind character --template a --joint pin
# Отдельная ПЛАТНАЯ операция, только по явному согласию:
tflex-hi3d split --mesh .\models\figurine.glb --kind character --template a --joint pin --yes-spend-credits
tflex-hi3d split-status TASK_ID --wait
tflex-hi3d split-download TASK_ID --output .\models\character_split.glb
# ЛОКАЛЬНЫЙ безопасный экспорт отдельных элементов, кредитов не тратит:
tflex-extract-parts .\models\character_split.glb --height-mm 120 --output-dir .\builds\split_to_print
```

`tflex-extract-parts` проверяет замкнутость каждого отдельного элемента и готовит `assembly/part_XX.stl` (общая координатная система для T-FLEX), `print/part_XX.stl` (каждый на столе Z=0), `parts.csv` и `assembly.json`. **Положительная проверка этой команды не подтверждает допуски суставов, прочность и толщину.** Чтобы печатать разными цветами на одноэкструдерном принтере, печатают разные файлы по одному, меняя катушку между партиями.

Windows T-FLEX 18 мост поддерживает готовые Hi3D split GLB через параметр `-SemanticParts` у PowerShell-скрипта `scripts/windows/tflex18_prepare.ps1`. В обычном режиме использует локальный 2-part Blender cut. **Ни одно действие Split-to-Print не запускается автоматически после генерации модели**: Hi3D Split имеет отдельную стоимость.

## Модульная печать и соединители

**Условно принят FDM принтер**, потому что пользователь указал одноцветный принтер, но не сообщил технологию. Это не гарантия — одноцветным бывает и фотополимерный принтер. До реального заказа требуется проверить FDM/SLA, сопло/материал/габариты.

Порядок:

```powershell
tflex-pipeline .\models\hi3d.glb --height-mm 120 --up-axis y --output-dir .\builds\hi3d-120
tflex-split .\builds\hi3d-120\exports\hi3d.stl --output-dir .\builds\hi3d-120-pieces --cut-ratio 0.5 --pin-diameter-mm 3 --clearance-mm 0.20
```

Настройки **для пробного FDM-изготовления**, не абсолютные правила:
- Штифт 3 мм диаметром.
- Диаметр посадочного отверстия 3,40 мм: радиальный зазор 0,20 мм с каждой стороны.
- Глубина отверстия в каждой части 5,5 мм; штифт чуть короче общей глубины.
- Два штифта на стык вместо одного, чтобы соединение не проворачивалось.
- Первым печатать `print/test_socket.stl` и один `print/pin_1.stl`; подгонять фактический зазор после измерения.
- Печатать `print/lower.stl` и `print/upper.stl` отдельно, в нужном количестве. Можно менять катушку между партиями, если в итоге нужна разноцветная фигурка даже с одним экструдером.

Файлы результата:

```
builds/hi3d-120-pieces/
  assembly.json
  parts.csv
  python_audit.json
  assembly/lower.stl
  assembly/upper.stl
  assembly/pin_1.stl
  assembly/pin_2.stl
  print/lower.stl
  print/upper.stl
  print/pin_1.stl
  print/pin_2.stl
  print/test_socket.stl
```

**Важная граница:** это 2 части и два вставных штифта на *плоском горизонтальном шве*; автоматического смыслового разделения волос/головы/туловища/конечностей нет. Если шов попадает на лицо, пальцы или тонкую область, **меняйте `--cut-ratio` и проверяйте результат; не печатайте плохую сборку**. При недостаточной толщине под штифты скрипт должен остановиться, а не просверлить фигурку насквозь.

## Подключение к T-FLEX CAD 18

1. На Windows установить T-FLEX CAD 18, Python 3.11 и Blender 4.x; в каталоге репозитория выполнить `py -3 -m pip install -e ".[dev]"`.
2. В CAD выбрать **Начало работы → Настройки → Настройка → Команды пользователя**.
3. Добавить команду типа **Внешнее приложение**. Указать `scripts/windows/tflex18_prepare.cmd` (либо путь к `powershell.exe` с аргументами `-NoProfile -File "path\to\tflex18_prepare.ps1"`).
4. Запустить команду: выбрать GLB/STL/OBJ, указать высоту/отношение разреза; результаты сохраняются в `Документы\T-FLEX-Figurines`.
5. Вставить `assembly/*.stl` в T-FLEX как 3D-изображения с одним и тем же положением, масштабом в мм. Это полигональная сборка, **не** параметрические CAD-тела.
6. Проверить `print/*.stl` в PrusaSlicer / OrcaSlicer / другом слайсере. Проверить тонкие части, опоры, ориентацию, физическую посадку и реальный калибровочный образец.

**Нативная Open API DLL не объявляется готовой**: её нельзя корректно собрать и испытать без Windows + `T-FLEX CAD 18\API\StarsPlugin` и разрешающей API лицензии. Пользовательская внешняя команда работает независимо и не требует подмены CAD API.

## Запрет на преждевременный «готово к печати»

`is_watertight` и успешное булево разрезание доказывают только базовую топологическую замкнутость. Самопересечения, толщины стенок, механическую прочность, размеры платформы, поддержку нависаний и принтер не проверяют. **До физической проверки `print_ready_certified=false`.**
